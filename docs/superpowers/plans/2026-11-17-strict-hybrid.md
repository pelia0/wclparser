# Strict lossless API/browser hybrid

User priority: fetch through the API, retain every browser field, never lose historical data. A replay-only patch cannot prove absence of unknown canonical browser fields. Ruling: implement strict verification against a complete browser canonical stream plus its replay, rather than claiming a lossy shortcut is equivalent. This retains browser traffic and must be explicit in the UI/README. Existing archives stay unchanged.

Architecture: a new HybridClient composes the existing protocol/API and browser clients with **separate FightArchive instances**, so asynchronous browser/API capture scopes cannot mix. API supplies the primary event stream. Browser downloads its complete canonical/replay streams independently. After both finish, the primary archive absorbs browser replay plus auxiliary browser canonical/master records, preserving every source response and source identity. The four-section WCLF3 container remains readable: auxiliary records are complete logical templates in metadata, not substituted into API responses. Unknown fields and Decimal values remain exact.

User steering: API workers MUST NOT wait for browser workers. Add durable `API_STAGED` phase (`needs_browser=1`) with its own independent browser-enrichment worker pool. API-only report preparation/download publishes a checksummed raw snapshot and immediately frees its API slot. Browser workers later load that snapshot, fetch all browser sources, merge into an isolated restored archive, and publish a new verified hybrid snapshot before relinking the row as STAGED. Only then may packing run. Old API snapshots are removed only after the enriched snapshot and DB link are durable. On failure/cancel/restart, retry enrichment without redownloading valid API data. Queue growth is on disk; no artificial browser backpressure on API downloads.

Interfaces for codec: `FightArchive.merge_hybrid_fight(browser_archive, report_code, fight_id)` validates identity/bounds/event alignment then attaches browser sources to the API completed capture and releases only that browser attempt; `discard_fight(report_code,fight_id)` releases only a failed/cancelled attempt; `full_fight_events(report_code,fight_id)` returns a merged view (API existing values win, absent browser canonical/replay fields fill in; differences remain in original source responses and hybrid manifest diagnostics). Reader `read_full_events(path)` supplies the same merged view while `read_raw_events` and source reconstruction stay API-exact. `full_events_json` and derived readers use full view. Staging preserves auxiliary records once and reconstructs merged raw_events on load. Any mismatch or missing/incomplete stream fails the fight; no fallback certifies partial data.

Interfaces for HybridClient: constructor `(api_client, browser_client, raw_archive, browser_archive)`; `requires_browser_enrichment=True`; `unarchive_report`, `fetch_report_master_and_fights`, `fetch_all_fight_events` use ONLY API and mark completed manifest `hybrid_pending=True`. `enrich_staged_fight(job, restored_api_archive)` independently fetches browser metadata/events and merges into the restored archive; returns browser metadata for packing inputs. Discovery delegates to browser. Different provider metadata caches must check matching source retention; cancellation awaits owned children and discards only the specific browser attempt, never global clear. Both archives use existing bounded caches.

Integration: add explicit `hybrid` source option, require saved user OAuth before hybrid start/import; create a dedicated browser archive/client. Harvester Stop drains owned network work and writers while retaining the visible browser for login/inspection, consistent with existing browser mode. Explicit Close Browser and application shutdown close both clients. Apply download request limits to any live browser client, retain FIFO/M+ and independent disk packing. Keep browser/API modes compatible and avoid automatic mode switch or server restart.
